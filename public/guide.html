🌐 Adding a Custom Domain & Going Live

Yes — you can absolutely add your own domain and go live for real. Here's exactly how, step by step.

The Short Answer

Yes, you can connect a custom domain like creatihub.com or yourbrand.com and the platform will function fully — users can sign up, order services, pay through Paystack, and you'll make real money. The app is a complete Node.js/Express server, so it runs on any hosting platform that supports Node.

Step-by-Step: From Local to Live

1Buy a domain name
Go to a registrar like Namecheap, GoDaddy, or Cloudflare Registrar. Search for your desired name (e.g., creatihub.com). A .com domain costs about $10–15/year. If your preferred name is taken, try .io, .co, or .ng (if targeting Nigeria).
2Choose a hosting platform
You need a host that runs Node.js apps (not just static HTML). Good options:
• Render.com — Free tier available, very easy. Connects to your GitHub repo and deploys automatically. Great for starting out.
• Railway.app — Similar to Render, generous free tier, excellent for Node apps.
• Fly.io — Good free tier, deploys from Docker.
• DigitalOcean App Platform — $5/month, more reliable for production.
• Vercel / Netlify — Only for the frontend; you'd need a separate backend host. Not recommended for this full-stack app.
• A VPS (DigitalOcean Droplet, Linode, Hetzner) — Full control, $4–6/month. You run npm install && node server.js with a process manager like PM2. Best for when you have real traffic.
3Deploy your code
Push your CreatiHub project to a GitHub repository (private is fine). Then on your chosen hosting platform, connect that repo. The platform will run npm install and start node server.js automatically. Set the start command to node server.js and the port to whatever the platform assigns (the app already reads process.env.PORT).
4Set your environment variables
On the hosting platform's dashboard, add these environment variables:
PAYSTACK_SECRET_KEY=sk_live_your_real_key_here PAYSTACK_PUBLIC_KEY=pk_live_your_real_key_here NODE_ENV=production PORT=3000 (or whatever the platform assigns)
The .env.example file in your project shows all available variables.
5Connect your custom domain
On the hosting platform, find the "Custom Domains" or "Settings → Domains" section. Add your domain (e.g., creatihub.com) and www.creatihub.com. The platform will give you DNS records to add — usually an A record or CNAME. Go to your domain registrar's DNS settings and add those records. DNS propagation takes 5 minutes to 48 hours (usually under 30 minutes). The hosting platform will automatically provision a free SSL certificate (HTTPS) for your domain via Let's Encrypt.
6Test it live
Once DNS propagates, visit https://creatihub.com. Register a test account, browse services, place a test order, and (once Paystack is configured) make a small real payment to verify the full flow works end-to-end.
✅ Your app is already production-ready in structure
It has token-based auth, password hashing, admin controls, payment integration, AI safety guardrails, and a real-time dashboard. The main things you need to do before launch are listed in the checklist at the bottom of this guide.

💳 Making Real Money — Payment Setup

The platform has Paystack payment integration built in. Here's how to switch from demo mode to real money.

Switching Paystack from Demo to Live

Right now, your app likely runs in Paystack demo/test mode. To accept real payments, you need to switch to Paystack live keys.

1Create/verify your Paystack business account
Go to paystack.com, sign up or log in. Complete business verification — Paystack requires your business name, address, and bank account details. For Nigeria, you'll need a BVN and business registration (CAC). For other African countries, requirements vary. This process typically takes 1–3 business days.
2Get your live API keys
In the Paystack dashboard, go to Settings → API Keys & Webhooks. Toggle from "Test" to "Live" mode. Copy your Live Secret Key (sk_live_...) and Live Public Key (pk_live_...).
3Set the keys in your environment
Replace the test keys with live keys in your hosting platform's environment variables:
PAYSTACK_SECRET_KEY=sk_live_your_real_secret_key PAYSTACK_PUBLIC_KEY=pk_live_your_real_public_key
Never put live keys in your code or GitHub. Always use environment variables. The app already reads from process.env.PAYSTACK_SECRET_KEY.
4Set the webhook URL
In Paystack's dashboard, set your webhook URL to https://creatihub.com/api/paystack/webhook (replace with your domain). This lets Paystack notify your app when a payment succeeds, even if the user closes their browser. Enable the "Charge Success" event.
5Set your callback URL
The app redirects users to /payment-callback after payment. Make sure your Paystack dashboard callback URL is set to https://creatihub.com/payment-callback.
⚠️ Paystack availability
Paystack currently operates in Nigeria, Ghana, Kenya, South Africa, Ivory Coast, Egypt, Rwanda, Tanzania, Uganda, and Botswana. If your target market is outside Africa, you'll need a different payment processor — Stripe (global), PayPal, or Razorpay (India). The payment code would need to be adapted for a different provider.

How the Money Flow Works

When a customer orders a service: (1) they select a package and see the price you set in the admin dashboard, (2) they click "Pay" and are redirected to Paystack's secure checkout, (3) they enter card details on Paystack's page (you never see or store card numbers — this is PCI-DSS compliant by design), (4) Paystack processes the payment and redirects back to your site, (5) your webhook confirms the payment and marks the order as paid. Paystack settles the money to your bank account — typically next-day for Nigerian accounts, or on a set schedule for other countries. Paystack charges a fee per transaction (around 1.5–3.9% depending on country).

Setting Your Prices for Profit

You already have the pricing editor in your admin dashboard (sidebar → "Pricing & Services"). You can set any price from $1 to $10,000 per package. Consider your costs: each service (flyer design, video creation, etc.) presumably has a fulfillment cost — whether that's your time, a freelancer, or an AI tool subscription. Set your price at least 2–3x your cost to ensure healthy margins. The quick-discount feature (10–50% off) is great for promotions and seasonal sales. Every price change is logged in the price history, so you can track what works.

Security Features Already Built In

  • Passwords are hashed with SHA-256 + salt (never stored in plain text)
  • Password reset codes expire after 15 minutes and can only be used once
  • Forgot-password endpoint doesn't reveal whether an email exists (no account enumeration)
  • Changing password revokes all existing tokens (forces re-login on all devices)
  • Admin can reset any user's password from the Security & Access panel
  • Invalid/expired tokens are rejected with 401
  • Minimum password length of 6 characters enforced on registration and reset
  • Duplicate email registration is blocked (409 conflict)
⚠️ Before going live — enable real email delivery
Right now, password reset codes are shown on screen (demo mode). In production, you need to wire up an email service so reset codes are actually emailed to users. Open db.js, find the sendEmail() function, and connect it to an email provider like Resend, SendGrid, Nodemailer + SMTP, or Amazon SES. The function is already called in all the right places — you just need to make it actually send.

🔴 Challenges You'll Face NOW (Before Launch)

These are the things you must address before going live with real customers and real money.

Challenge Why It Matters How to Fix Priority
JSON file database Your app stores all data in a single db.json file. This works for development but will corrupt under concurrent writes, has no backup, and will lose data if the server restarts unexpectedly. Most hosting platforms use ephemeral filesystems — your db.json gets wiped on every deploy. Migrate to a real database. Easiest path: MongoDB Atlas (free tier, cloud-hosted, no setup). Replace the file-based load()/save() in db.js with Mongoose models. Alternatively, use SQLite with better-sqlite3 (single file, but survives restarts) or PostgreSQL (free on Supabase/Neon). This is the single most important change before launch. CRITICAL
Email delivery not configured Password reset codes, order confirmations, and admin notifications are queued but not actually sent. Users can't recover their accounts if they forget their password in production. Wire up sendEmail() in db.js with a provider: Resend (easiest, 3000 free emails/month), SendGrid (100/day free), or Nodemailer + Gmail SMTP (free but limited). Remove the demoCode from the forgot-password API response once email works. CRITICAL
Paystack test vs live keys Currently in demo/test mode — no real money is processed. Customers' payments won't go through. Get Paystack live keys after business verification. Set PAYSTACK_SECRET_KEY and PAYSTACK_PUBLIC_KEY environment variables to live keys. Set webhook and callback URLs in Paystack dashboard. CRITICAL
HTTPS / SSL Without HTTPS, passwords and payment data travel in plain text. Paystack requires HTTPS for live integration. Browsers will block API calls from HTTP. Most hosting platforms (Render, Railway, Fly.io) provide free SSL automatically. If using a VPS, install Caddy or Nginx + Certbot for free Let's Encrypt certificates. CRITICAL
Default admin password The admin password is admin123 — anyone who sees the demo or the code can log in to your admin dashboard. Change it immediately after deployment: log in → Dashboard → Profile → Change Password. Use a strong password (12+ characters, mixed case, numbers, symbols). Or better: change it directly in the database before deploying. HIGH
No rate limiting on auth endpoints Someone could brute-force login passwords or spam password reset requests. The AI chat has rate limiting, but the auth endpoints don't. Add express-rate-limit middleware: limit login to 5 attempts per 15 minutes per IP, limit forgot-password to 3 per hour. Install: npm install express-rate-limit. HIGH
Session tokens stored in memory Tokens are stored in the db.tokens object. If the server restarts, all users are logged out. With a JSON database, this resets on every deploy. With a real database (MongoDB/PostgreSQL), store tokens in a sessions collection/table. Or switch to JWT (stateless tokens) so no server-side storage is needed. MEDIUM
No automated backups If db.json is corrupted or deleted, you lose all users, orders, and data. There's no backup mechanism. With a real database, backups are handled by the provider (MongoDB Atlas, Supabase, etc. all have automatic backups). If staying with JSON temporarily, set up a cron job to copy db.json to cloud storage (S3, Google Drive) every hour. MEDIUM
Service fulfillment workflow When a customer pays, the order is marked as "paid" — but there's no automated system to actually deliver the service (flyer, video, logo). You need to manually fulfill each order. For now, check the admin dashboard → Orders regularly and fulfill manually. Later, you can add: automated email to the customer with delivery timeline, freelancer assignment system, file upload/delivery portal, and order status notifications. MEDIUM
Legal pages missing You need Terms of Service, Privacy Policy, and Refund Policy to operate legally and to be accepted by Paystack and app stores. Create /terms, /privacy, and /refund pages. You can use a generator like termsfeed.com or privacypolicies.com, then customize for your business. Link them in the footer. MEDIUM

🟣 Challenges You'll Face LATER (After Launch)

These aren't blockers for launch, but you'll need to address them as you grow.

Challenge When It Hits How to Handle It Priority
Scaling to high traffic When you get 100+ concurrent users, the single Node process and JSON database will slow down or crash. Migrate to a real database (MongoDB/PostgreSQL) first. Then run multiple Node instances behind a load balancer (most hosting platforms do this automatically with "scale to N instances"). Add Redis for caching and session storage. SCALE
AI assistant is rule-based, not an LLM As customers ask more complex/varied questions, the keyword-matching AI will fail to answer them, leading to poor support experience. Integrate a real LLM (OpenAI GPT, Anthropic Claude, or Google Gemini) behind the same safety guardrails you already have. The filterMessage() function and audit trail work regardless of the AI engine — you'd just replace the response generation. Keep the kill switch and blocked-phrases system. GROWTH
Payment disputes and chargebacks A customer disputes a charge through their bank. Paystack will notify you, and you may lose the money plus a dispute fee. Keep clear records of every order and delivery. Have a strong refund policy. Communicate clearly with customers. Respond to disputes promptly with evidence (delivery proof, communications). Paystack's dashboard shows dispute status. ONGOING
Fraud and fake orders Someone uses a stolen card to pay, or creates fake accounts to spam your system. Paystack has built-in fraud detection — enable it in your dashboard. Add email verification on registration (send a confirmation link). Monitor the AI audit trail for suspicious patterns. Consider adding CAPTCHA on registration if spam becomes an issue. ONGOING
Data privacy compliance If you serve EU customers (GDPR), Nigerian customers (NDPR), or California residents (CCPA), you must comply with data protection laws — right to access, right to deletion, data portability. Add a "Delete my account" feature in the user dashboard. Add a data export feature. Document your data retention policy in your Privacy Policy. Only collect data you actually need. COMPLIANCE
Customer support volume As orders increase, you'll get more support messages. The AI handles FAQs, but complex issues need human attention. The admin dashboard already shows all support messages and AI activity. Set up email notifications for new support messages (already partially built via notify()). Consider integrating a help desk tool (Zendesk, Crisp) if volume grows beyond what the dashboard can handle. GROWTH
Currency and pricing complexity The app supports 12 currencies, but actual multi-currency payment processing (charging in the customer's local currency) requires Paystack configuration per currency. Paystack processes in the currency of your account (e.g., NGN for Nigerian accounts). For true multi-currency, you'd need separate Paystack accounts per currency region or a processor like Stripe. For now, display prices in the customer's currency but charge in your base currency with appropriate conversion. GROWTH
Service quality consistency If you're fulfilling orders yourself or with freelancers, quality may vary. Bad reviews will hurt your reputation. Create service standards and templates. Use the same freelancers for consistency. Add a review/rating system so customers can feedback. Monitor order completion times in the admin dashboard. GROWTH
Competitor pressure Fiverr, Upwork, 99Designs, and local competitors will be competing for the same customers. Differentiate on: faster delivery, local payment options (Paystack gives you an edge in Africa), niche specialization, better AI-powered experience, competitive pricing (use your pricing editor to experiment), and strong customer service. STRATEGY
Code maintainability The codebase is a single Express file (server.js ~800 lines) with a JSON database. As features grow, it becomes harder to maintain. Eventually refactor into: separate route files (routes/auth.js, routes/orders.js, etc.), a proper database layer, environment-based configuration, and automated tests (you already have test scripts — formalize them with Jest/Mocha). This isn't urgent but plan for it after 3–6 months of growth. TECH DEBT

🤖 Autonomous AI — Things Nova Can Do On Its Own

Right now Nova is a reactive assistant — it only responds when a user or admin sends a message. Below are concrete features we can add so Nova acts on its own without human prompting, organized by priority. Each one is buildable with the existing codebase.

🎯 Ready to Build Now (Uses Existing Data & Infrastructure)

📧 Auto Order Confirmations & Status Emails

When an order is placed, paid, or completed, Nova automatically generates and sends a personalized email to the customer — no admin action needed. Uses the existing sendEmail() function and order lifecycle hooks.

EASY
🔔 Smart Admin Alerts

Nova monitors the store and proactively notifies the admin when something needs attention: a new order came in, a payment failed, an order is overdue, a customer hasn't been responded to in 24 hours. Shows up in the existing real-time activity feed and notification bell.

EASY
📈 Weekly Business Report (Auto-Generated)

Every Monday at 9 AM, Nova compiles a summary of last week's performance — total revenue, number of orders, best-selling services, new customers, compared to the previous week — and sends it to the admin email and posts it in the dashboard. Uses the existing adminAssistant() analytics logic.

EASY
💬 Auto-Follow-Up on Abandoned Carts

If a customer starts checkout but doesn't complete payment within 30 minutes, Nova automatically sends a friendly reminder email with a link to resume. Can include a small AI-generated discount to encourage completion.

MEDIUM
🎨 Auto-Generate Service Descriptions & SEO Tags

When you add a new service in the admin dashboard, Nova automatically writes a compelling description, generates SEO keywords, and suggests a competitive price based on similar services in your catalog. One click to approve or edit.

MEDIUM
⏰ Delivery Deadline Reminders

Nova tracks order deadlines and automatically sends reminders to the admin 24 hours before a delivery is due, and to the customer when their order is ready. Prevents missed deadlines without manual tracking.

EASY

🚀 Medium Priority (Requires Some New Infrastructure)

📱 Auto Social Media Content Generation

Nova generates promotional posts for your services automatically — one per day for Instagram, Twitter/X, and Facebook. Writes the caption, suggests hashtags, and queues it for your approval. You review and post, or connect an API to auto-post.

MEDIUM
🏆 Customer Review Auto-Responses

When a customer leaves a review, Nova automatically drafts a personalized response — thanking them for positive reviews, and addressing concerns in negative ones with an apology and next steps. Admin approves before sending, or Nova auto-responds for 4-5 star reviews.

MEDIUM
📊 Dynamic Price Optimization

Nova analyzes demand patterns and suggests price adjustments: increase price for high-demand services, lower it for slow movers. Generates a weekly recommendation report. Admin can enable auto-adjust with a maximum percentage cap.

ADVANCED
🎯 Personalized Service Recommendations

Nova learns from each customer's browsing and purchase history, then automatically recommends relevant services on their dashboard and in follow-up emails. "Based on your logo design order, you might also need business card design…"

MEDIUM
🛡️ Fraud Detection & Order Flagging

Nova automatically scans new orders for suspicious patterns: unusually large amounts, rapid repeat orders from the same IP, mismatched billing details. Flags risky orders for admin review before fulfillment. Reduces chargeback risk.

MEDIUM
🎁 Auto-Generated Promotional Campaigns

Nova identifies slow periods and automatically creates promotional campaigns — discount codes, bundle offers, seasonal specials — with suggested target audiences and email drafts. Admin approves with one click.

💡 How These Work Technically

All autonomous features use the same pattern: a background scheduler (a setInterval or node-cron task) that runs periodically, checks conditions in the database, and triggers actions through existing functions (sendEmail(), logActivity(), notify(), logAiActivity()). Nova's autonomous actions show up in the same real-time admin activity feed you already have, so you always know what the AI is doing. Each feature can be toggled on/off from the admin dashboard, and all autonomous AI actions are logged to the existing audit trail for safety.
